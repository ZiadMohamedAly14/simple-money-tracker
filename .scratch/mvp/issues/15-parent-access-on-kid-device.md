# 15: Parent access on a kid's device

**What to build:** A parent reaches the Parent Area on their child's phone by entering the PIN while online. They can also manage and revoke Kid-Mode devices and reset a forgotten PIN.

**Blocked by:** 14 (Kid-Mode device).

**Status:** resolved

- [x] PIN elevation: the server checks the PIN with rate limiting and returns a short-lived full access token with no refresh. When offline, the device explains that the Parent Area needs internet.
- [x] Leaving Kid Mode requires the PIN.
- [x] Kid-Mode devices can be listed and revoked from the Parent Area. A revoked device is signed out on its next sync.
- [x] A forgotten PIN can be reset with an email code.
- [x] Seam A tests cover elevation, its rate limit, revocation and PIN reset.

## Comments

Built on `ticket/15-parent-access-on-kid-device` (merged with `mvp` after ticket 18):

- **Shared:** `ElevateBody`, `ElevatedAccessData` (`accessToken`, `expiresInSeconds`), `ElevateErrorData`, `KidDeviceSummary`, `KidDevicesData` (`kid/kidDevice.ts`); `RequestPinResetBody`, `ResetParentPinBody` (`pin/parentPin.ts`).
- **API, PIN elevation:** `POST /kid-devices/elevate { pin }`, Kid Session only (a full session gets 403 `not_kid_session`). It checks the PIN with 11's `checkPin`, so it shares the Account's throttle (403 `wrong_pin` / 429 `pin_locked`), and 409 `no_pin` if no PIN is set. It starts a full-scope Session that lasts as long as one access token (15 min) and never gets a refresh token. That Session has `elevatedFrom` (the Kid Session) and the same `kidProfileId` and `deviceLabel`. `authenticate` now returns the stored `kidProfileId` for any session, plus `elevatedFrom`. Sync pulls by `kidProfileId`, so an elevated kid phone can push Top-ups and Jar Transfers with full rights but still pulls only its kid's records (ADR-0002: no Personal data on that phone). It doesn't create the Other Category.
- **API, sessions:** `tokens.endSession(id)` now deletes the Session and any elevation from it (logout, reuse revocation, revoke). 18's `endKidSessions` now matches on `kidProfileId` without `scope: 'kid'`, so archiving a kid ends elevations from that kid's phones too. Personal sessions have no `kidProfileId`.
- **API, devices:** `GET /kid-devices` (full access) lists live Kid Sessions newest first: `id`, `kidProfileId`, `deviceLabel` (the kid's name), `createdAt`, `lastActiveAt` (last refresh), and `current` (the elevated phone asking). `DELETE /kid-devices/:id` (full access) revokes one. Another Account's or a non-kid session gets 404.
- **API, PIN reset:** `POST /account/pin/reset-code { language }` and `POST /account/pin/reset { code, pin }`, full sessions only. They reuse the sign-in code machinery (`auth.service` now has `useCode`, and `requestCode` takes a `purpose`), so the resend limits, guess limits and expiry are the same. The email has its own EN/AR "PIN reset" copy. A reset clears the wrong-PIN lock. No new collection.
- **Seam A** (`apps/api/test/parentAccess.test.ts`, 16 tests): elevation (token works with full access and stops after 15 min, no refresh token, the Kid Session carries on), the rate limit, scope and validation, a Top-up from the elevated phone pulling only that kid, listing (labels, order, `current`, other Accounts hidden), revoking (from the parent or an elevated kid phone, which also ends elevation; refusals), archiving ending elevation, and PIN reset (new PIN works, old one doesn't, Arabic email, clears the lock, wrong/used/expired codes, guess limit, Kid Session refused, validation).
- **Mobile, data:** `authSession.elevate(pin)`, `elevated()`, `elevationEndsAt()`, `endElevation()`, `leaveKidMode()`. The elevated token is kept **in memory only** and is used for every call until 30 s before it expires. If it gets a 401, the call falls back to the Kid Session. **A Kid-Mode device whose session the server ends is signed out with its local data wiped** (`forget`, from 18, now also drops elevation) and goes back to sign-in. This covers revoking, archiving the kid and deleting the Account alike. `leaveKidMode({ auth, sync })` (`src/kid/kidDeviceSetup.ts`) needs elevation, syncs first and refuses offline so nothing is lost, then logs the Kid Session out and wipes. `src/kid/kidDevices.ts` lists and revokes devices. `parentPinGate.requestReset` and `resetPin` store the new hash and clear the device throttle.
- **Seam B** (`src/kid/parentAccess.seamB.test.ts`, 11 tests): top-up from the elevated kid phone reaching the parent while the phone holds only its kid; offline, wrong PIN, not kept across restart, local expiry; listing from both phones and offline; revoked, archived and Account-deleted kid phones wiped and back at sign-in; leaving Kid Mode (needs PIN, pushes the last Kid Expense, ends the session; waits offline); PIN reset (wrong code, clears lock, kid phone takes the new PIN) and refused on a Kid-Mode device.
- **Screens:** the kid's home has a Parent Area button (`app:lock-pin`). On a Kid-Mode device, `parent/_layout` shows a server-checked PIN gate. It shows an `app:offline` notice ("needs the internet") up front via expo-network or after an unreachable try, the lock countdown, and "Forgot PIN?", which explains how to reset from the parent's own phone (`app:key`). The route allow-list moved to `src/kid/kidModeRoutes.ts` (`kidModeAllows`, unit tested). It always opens `/parent` (the gate) and opens `parent/kids/*` and `parent/devices` only while elevated. `parent/kids/new` and `parent/kid-device` stay closed. On a kid phone the Parent Area shows Kid-Mode devices, Leave Kid Mode (`app:exit`, with a confirm) and Lock. Locking syncs first, then ends elevation, and the area locks itself when the token runs out or the app goes to the background. New `parent/devices` (`app:devices`, `app:revoke-device`; the phone in hand is marked "This phone" and has no remove button) and `pin/reset` (`app:email`; send code, code boxes and keypad, new PIN, confirm). "Forgot PIN?" is on the Personal gate too. EN/AR strings are under `parentAccess.*`, `pinReset.*` and `pin.forgot`. `devices`, `revoke-device` and `key` are no longer in `RESERVED_APP_ICONS`.

**Left over / notes:**
- Say the elevated token runs out (or the phone goes offline and stays offline) after the parent made a Top-up on the kid's phone but before it synced. Then the outbox holds a change the Kid Session can't push, and the kid's syncs are refused (403) until the next elevation pushes it. Locking syncs first, and the Parent Area there needs the internet, so the window is small. A fix would hold parent-only changes back from kid-scope pushes.
- On an elevated kid phone, the kid's detail screen still shows 18's Archive button. Archiving the phone's own kid signs that phone out (by design). Hiding it there is a small follow-up if wanted.
- PIN reset is full-session only. On a kid's phone, "Forgot PIN?" points to the parent's phone (or any phone the parent signs in on).
- Leaving Kid Mode signs the phone out rather than turning it into a Personal device, so the full tokens are never kept on a kid phone (ADR-0002). The parent signs in again by email to use it as their own.
